# plan/03 · 模块详设与 CLI 契约

> 数值口径（T1–T12 / 归一化 op / 树摘要 / 退出码 / `|S|≤12` / 幂等）**只在 `data/README.md` §四定义**。本文件是便于阅读的摘录，冲突时以 §四 为准并在同一提交修正摘录。

## 一、CLI 契约总表

| 命令 | 作用 | 主要参数 | 退出码 |
|---|---|---|---|
| `bdiff align` | 结构对齐，出条目表 | `--left` `--right` `--format json\|md` `--layer-kind=oci` | 0 成功 / 1 用法或不可解析 |
| `bdiff facts` | 事实抽取 | `--artifact`（单侧） `--format json` `--layer-kind=oci` | 0 / 1 |
| `bdiff compare` | 归因 + 最小集 + 报告 | `--left` `--right` `--out <dir>` `--format json\|md\|both` `--budget=T1,T2` `--layer-kind=oci` `--fail-on=any\|residue` | **0/1/2/3**（见 §三.5） |
| `bdiff version` | 版本 | — | 0 |
| `bdiff selftest` | 内置自检（不联网、不用样张） | — | 0 / 1 |

> 分阶段落地：M3 起 `compare` 先输出**归因 JSON**（`counts`/`diffs`/`residue_bytes`/`tree_digest`/`notes`）
> 并按 §4.6 返回 0/2/3；`--out` 的 `report.json`/`report.md` 落盘、`--format=md|both`、最小原因集与
> `--fail-on` 在 M4–M5 补齐。

**参数形态纪律**（阶段 7 出口门①的预防）：多值参数 `--budget` **只接受逗号分隔**（`T1,T2`），并**同时**接受 `all` 与空串（= 无白名单）。`align/facts/compare` 的 `--format` 用 `choices` 语义（Go 里手写校验），`selftest` 与 `README` 里出现的每条命令都必须能被 parser 接受（常驻测试 `TestReadmeCommandsParse`，M5 落地）。

**未知参数 / 缺必填** → exit 1（不是 2——2 是"仅元数据差异"这个业务语义，不能被用法错误占用）。

## 二、模块① `align` — 结构对齐

**输入**：`--left` / `--right`，每个是目录 / `tar` / `tar.gz` / `zip` / `whl` / `jar` / OCI layer tar。

**输出**（`--format json`）：

```json
{
  "schema_version": 1,
  "left":  {"kind": "zip", "entries": 12, "total_bytes": 4096},
  "right": {"kind": "zip", "entries": 13, "total_bytes": 4201},
  "entries": [
    {"relpath": "pkg/__init__.py", "status": "SAME",    "kind": "file", "size": 120, "sha256": "…"},
    {"relpath": "pkg/new.py",      "status": "RENAMED", "kind": "file", "size": 90,  "sha256": "…", "renamed_from": "pkg/old.py"}
  ],
  "counts": {"SAME": 11, "ADDED": 1, "REMOVED": 0, "RENAMED": 1}
}
```

**四类状态的精确语义**（M1 落地，`data/README.md` §4.9 同一口径）：

- `SAME` = 两侧存在同 relpath 且同形态。**结构对齐 ≠ 内容一致**：内容是否相同由 attribute 判定，
  否则每一处 T12 都会被重复记成"删一个 + 加一个"，报告里的 `added`/`removed` 会被内容差异污染。
- `RENAMED` = 路径只在单侧出现，且该 sha256 在两侧**各出现 1 次**（§4.4 三条）。
  行以**右侧（新）路径**作 `relpath`、以左侧（旧）路径作 `renamed_from`——JSON 示例已按此修正。
- `REMOVED` / `ADDED` = 其余情形（含同名异形态：两侧各记一条）。

**引擎**：

1. **装载**（`internal/artifact`）：目录树用 `filepath.WalkDir` 收集后排序；tar/tar.gz 用 `archive/tar` 流式读；zip/whl/jar 用 `archive/zip`；一律**解到内存**（单文件上限 `--max-entry-bytes`，默认 256 MiB，超限 → exit 1 并指名条目——安全阀必须可见，不静默丢弃）。
2. **规范化 relpath**：`filepath.ToSlash` → 去前导 `./` → 去重复 `/` → 拒绝 `..` 越界（越界 → exit 1，不静默改写成别的路径）。**不做大小写折叠**。
3. **对齐**：两侧按 relpath 求交并集。
4. **改名判定**（唯一允许的"跨路径识别"）：仅当 ① 左侧唯一 `REMOVED` 且右侧唯一 `ADDED`；② 两者 `sha256` 相等；③ 该哈希在两侧各出现 1 次。否则各自记 `ADDED`/`REMOVED`。
5. **目录条目**：`kind=dir` 的条目参与对齐与计数，但**不参与 `facts`**（无可抽取头部），`size=0`、`sha256` 为 `sha256("")` 的常量值（写进 `data/README.md` §4.9 常量表，M1 落地时补）。

**确定性**：`entries` 按 relpath 字节序；`counts` 键序固定 `SAME/ADDED/REMOVED/RENAMED`；双跑逐字节。

## 三、模块② `facts` — 事实抽取

**输入契约（M2 落地，`internal/artifact`）**：

```go
type Document struct { Kind Kind; Entries []Raw; Container Container }
type Container struct { Kind Kind; Facts []HeaderFact; RawHeader []byte }  // 容器级；facts 的 path = ""
type Raw struct {
    Path, Kind string; Size int64; Data []byte
    Index     int       // 归档内序号（0 起；目录输入 = -1）→ T5
    Source    Kind      // 条目实际来自的容器（OCI 层记录底层 tar / tar.gz）
    RawHeader []byte    // §4.3 的"未抽取头部字节"
    Tar *TarInfo        // tar 头字段（非 tar 条目为 nil）
    Zip *ZipInfo        // zip 头字段（非 zip 条目为 nil）
}
```

容器级事实（`gzip.mtime/xfl/os`、`zip.create_system`）不属于任何条目，`facts.ExtractContainer` 用空 `path` 输出；
`facts.ExtractDocument` 负责合并并按 `(path,key)` 排序。`align` 继续只用 `Raw` 的 Path/Kind/Size/Data 四项。

**输出**：`(path, key, value)` 扁平记录，按 `(path,key)` 字节序。`bdiff facts` 的外层是
`{"schema_version","kind","entries","facts"}`，`facts` 为该扁平数组（`data/golden/facts/` 逐字节钉住）。

**抽取面**（每个 key 一个单测；key 集合 = `facts.FixedKeys` + `TrackedSections` 派生）：

| 容器 | keys |
|---|---|
| tar | `tar.mtime` `tar.uid` `tar.gid` `tar.uname` `tar.gname` `tar.mode` `tar.typeflag` `tar.size` |
| zip | `zip.mtime`（`date_time`）`zip.external_attr` `zip.create_system` `zip.method` |
| gzip | `gzip.mtime` `gzip.xfl` `gzip.os` |
| ELF | `elf.build_id` `elf.comment` `elf.comp_dir` `elf.producer` `elf.section.<name>.offset` `elf.section.<name>.size` |
| PE | `pe.timestamp` `pe.checksum` `pe.rich.present` `pe.rich.digest` |
| Mach-O | `macho.uuid` `macho.minos` `macho.sdk` `macho.tools` |

**兜底硬纪律**：解析器未识别的头部/元数据区 → `raw_header_sha256`（覆盖范围与字节构造见 `data/README.md` §4.3）。任何"没看懂就跳过"的路径视为缺陷。

**数值格式**：十进制字符串；布尔 `"true"/"false"`；二进制串 lowercase hex；非 UTF-8 字符串写 `hex:` 前缀。
完整口径（含 `zip.mtime` 的 `YYYYMMDDHHMMSS`、节 key 的双点形态、容器级 `path=""`）只在 `data/README.md` §4.10。

## 四、模块③ `attribute` — 归因

**输入**：两侧 `facts` + 每个条目的内容字节与归档内序号（容器级事实作为 `path=""` 的条目）。
依赖方向 K4：`attribute` 只 import `model` / `facts` / `normalize`，装载由 `cli` 完成。

**输出**：

```json
{
  "counts": {"T1": 3, "T2": 0, "…": 0, "T12": 1, "total": 4},
  "diffs": [
    {"path": "pkg/a.py", "key": "tar.mtime", "rule_id": "T1", "left": "1700000000", "right": "1700003600", "bytes_delta": 0}
  ],
  "residue_bytes": 128,
  "tree_digest": {"left": "…", "right": "…", "normalized_all": "…"},
  "notes": []
}
```

`notes` 只放口径性提示（§4.1 的 `rule_overlap`），不参与判定。`tree_digest.normalized_all`
= 左侧在 S = T1–T11 下的摘要（§4.5）。

**分类顺序**：按 `T1 → T12` 取首个命中；命中两个以上 → 取首个并在 `notes` 记 `rule_overlap`（`data/README.md` §4.1 闭合性要求）。

**归一化**（`internal/normalize`）：每个 Tn 一个纯函数，`op(Tn, entryFactSet) → entryFactSet`（+ 条目字节流按需重写）。集合 S 的施加顺序 = **rule id 升序**。

**树摘要**：`tree_digest(S)` 按 §4.5 定义，代码里**唯一实现**在 `internal/normalize/digest.go`；`attribute` 与 `minimize` 都调它（`plan/02` §二 的"序列化唯一入口"同族纪律）。

**`residue_bytes`**：由**实际字节比对**得出（逐条目 `cmp` 计数），不由分类推导。T12 出现即 `residue_bytes > 0`。

## 五、模块④ `minimize` — 最小原因集

**算法**：

```
for size in 0..12:
    for S in combinations({T1..T12}, size) in lexicographic order:
        if tree_digest_left(S) == tree_digest_right(S):
            return S
return null
```

- 上界 2^12 = 4096 个候选，每个候选只做**一次**归一化 + **一次**摘要。
- 不剪枝、不随机、不启发（保"最小"可复算）。
- 破平：同基数按 `T1<T2<…<T12` 的字典序取第一个命中。
- `S=∅` 且两侧摘要相等 → 完全一致（不是"无解"）。
- 无解 → `null`，且**必须** `residue_bytes > 0`（两者同真才算合法输出，有断言）。

## 六、模块⑤ `report` — 报告与门禁

**键序**（§4.8 写死）：`schema_version` → `tool_version` → `left` → `right` → `counts` → `renamed` → `added` → `removed` → `residue_bytes` → `minimal_cause_set` → `residual_items` → `notes`。

**`report.md`**：固定模板（标题 / 输入摘要 / 逐类计数表 / 改名·新增·删除清单 / 残留条目 / 最小原因集 / 结论行），**无时间性文案**，双跑逐字节。

**退出码判定（唯一实现 `internal/cli/exitcode.go`）**：

```
不可解析            → 1
T12 出现 或 residue>0 → 3
residue==0 且 S==∅   → 0
residue==0 且 S≠∅    → 实际类别 ⊆ budget ? 0 : 2
```

**`--budget`**：只影响 0/2 的判定；不得把 3 降级。报告里仍然逐条列出被放行的差异与计数（"放行"≠"消失"）。

**`ci/example.yml`**：一段可直接粘进 GitHub Actions 的门禁示例（下载 Release 二进制 → `bdiff compare --budget=T1,T2` → 用退出码当门）。本地可跑通（`node` 脚本或 bash 等价命令），不联网的部分在 M5 验证。

## 七、模块间数据契约（Go 类型）

```go
type Entry struct { RelPath string; Kind Kind; Size int64; SHA256 string }        // align
type Fact struct { Path, Key, Value string }                                      // facts
type Diff struct { Path, Key, RuleID, Left, Right string; BytesDelta int64 }      // attribute
type Budget []string                                                              // cli
type Report struct { … }                                                          // report（字段顺序 = 键序）
```

纪律：`Entry`/`Fact`/`Diff` 三型**不带指针字段**，便于深比较与 golden 断言；`Report` 用有序 struct + 单一 `MarshalCanonical`。
