# plan/02 · 架构与技术选型

> 上游：`plan/01-题目文档.md`（需求与验收）、`data/README.md` §四（数值口径唯一权威）。
> 本文件只定**分层、依赖方向、构建与确定性设计**；模块级行为在 `plan/03`。

## 一、技术选型（已定，不再讨论）

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | **Go（仅标准库）** | `archive/tar`、`archive/zip`、`compress/gzip`、`debug/elf`、`debug/pe`、`debug/macho`、`crypto/sha256`、`encoding/json` 全在标准库 |
| 依赖 | **零第三方模块**（`go.mod` 无 `require`） | 单二进制、可离线重建、干净机器无运行时 |
| 分发 | `dist/bdiff-<os>-<arch>`（`CGO_ENABLED=0`） | 静态二进制，`go build` 单命令 |
| 形态 | 纯本地 CLI，**不跑构建、不联网、不写输入目录** | 见 `plan/01` §六 |
| 版本 | `go 1.22`（语言特性下限） | 干净的 `for range int`/`slices` 之外不用新特性；CI 用 matrix 覆盖 |

**弃选记录**（完整版在 `plan/00` §二）：Python（需运行时，与"单二进制零依赖"冲突）、Rust（工具链在小机器上更重，标准库缺 PE/Mach-O 解析）、任何第三方归档库（把"零依赖"变成"可执行文件随依赖漂移"）。

## 二、分层与依赖方向

```
cmd/bdiff/                  CLI 入口：参数解析 → 调用 internal → 退出码
  └── internal/cli/         子命令定义与退出码映射（唯一 exit code 出口）
        └── internal/align/     结构对齐：路径 → 条目表（含 RENAMED 判定）
              internal/facts/   事实抽取：条目字节 → (path,key,value)
              internal/attribute/ 归因：两侧 facts → 差异点 + counts
              internal/minimize/  最小原因集：差异点 → minimal_cause_set
              internal/report/    报告：attribute+minimize → report.json / report.md
        └── internal/artifact/   输入装载（目录 / tar / tar.gz / zip / whl / jar / OCI layer）
        └── internal/normalize/  T1–T11 的纯函数归一化 op + tree_digest
```

**依赖方向（硬约束，有常驻测试）**：

```
cli → {report, minimize, attribute, facts, align}
report → {attribute, minimize}
minimize → normalize
attribute → {facts, normalize}
facts → artifact
align → artifact
normalize → (无内部依赖)
artifact → (无内部依赖)
```

规则：

1. **叶子层不许反向 import**（`artifact` 不得 import `align`；`normalize` 不得 import 任何内部包）。守门 = `internal/guard` 的 import 图测试。
2. **受限标准库黑名单**：`net`、`net/http`、`time`、`math/rand`、`os/exec`、`os/user` 在 `cmd/`、`internal/`、`tools/` 下一律禁止 import。这是"零网络 + 不读时钟 + 不读主机身份"的静态证据（布局门 `LAYOUT.NO_NET` + `internal/guard` 测试双份）。
   - 例外的处理方式：需要时间语义时用参数传入（`--source-date-epoch <int>`），不读 `time.Now()`。
3. **序列化唯一入口**：所有 JSON 输出经 `internal/report/jsonx` 的 `MarshalCanonical`（固定键序、无多余空白、LF 结尾）。子命令不得自行 `json.Marshal` 后写盘。

## 三、构建与运行

```bash
go build -trimpath -o dist/bdiff ./cmd/bdiff        # 单二进制
go test ./...                                       # 全量测试
go vet ./...
node tools/check-sprint-layout.mjs                   # 布局门（方法论装订）
go run ./tools/gen_fixtures --out data/fixtures --check   # 样张重建校验（M1 起）
```

构建纪律：

- **`-trimpath` 必带**：二进制里不得残留本机绝对路径（发布脱敏的一部分）。
- **`CGO_ENABLED=0`**：跨平台静态产物，无需目标机 glibc。
- 二进制**不入仓**（`.gitignore` 已排除 `dist/`），发布时手工上传 Release 并登记 sha256。
- 版本号**单一来源**：`internal/version/version.go` 的 `const Version`；`bdiff version` 与 `report.json.tool_version` 都取它；M6 定版只改这一处。

## 四、退出码契约（实现层）

唯一出口在 `internal/cli`：

| 码 | 含义 | 触发 |
|---|---|---|
| 0 | 完全一致 / 被 `--budget` 放行且归一化后一致 | 见 `data/README.md` §4.6 |
| 1 | 用法错误 / 输入不可解析 | 参数非法、路径不存在、归档损坏、不支持的格式 |
| 2 | 仅元数据差异 | 全部差异 ⊆ T1–T11 且归一化后 `residue_bytes == 0` |
| 3 | 有残留 | `residue_bytes > 0` 或出现 T12 |

纪律：子命令**返回** `(code int, err error)`，由 `cli.Run` 统一 `os.Exit`；禁止在深层包里调 `os.Exit`（否则测试无法断言，且退出码出口会散成多处）。

## 五、确定性设计（"双跑逐字节一致"的落法）

| 漂移源 | 处置 |
|---|---|
| 遍历顺序 | 归档条目按 `relpath` 的 **UTF-8 字节序**排序（`sort.Slice` + `bytes.Compare`）；目录遍历收集后排序，不信 `os.ReadDir` 的偶然顺序 |
| 时间 | 不产生"运行时刻"字段；`report.md` 不含日期文案；归一化 mtime 用固定 `0` |
| 路径 | 输出只写 `basename` + `sha256`；`filepath.ToSlash` 统一分隔符；不写绝对路径 |
| 主机身份 | 不读 `os.Hostname`、`os.Getenv("USER")`、`os/user`（黑名单守门） |
| 浮点 | 不使用浮点；所有计数是 `int64`，摘要/字节数是十进制整数 |
| JSON | 固定键序（手写序列化或有序 struct + 单一入口）；`SetEscapeHTML(false)`；`\n` 结尾；不缩进（`report.json`）/ 定长缩进（golden 需人读时由 `report.md` 承担） |
| 并发 | 首期**不用 goroutine 做输出聚合**（顺序不可控）；若为性能引入，必须"先收集后排序"，禁止边算边写 |
| 压缩 | 归一化重压用 Go `compress/gzip` 固定参数（`BestCompression`、无 Name/Comment、mtime=0），**不调用 `gzip` 可执行文件**（`os/exec` 已禁） |

**幂等**：`normalize_op(Tn, normalize_op(Tn, x)) == normalize_op(Tn, x)`，逐 op 单测（见 `plan/03` 模块③）。

## 六、错误与诊断

- 错误信息**中文 + 可操作**（"无法读取 `--left`：路径不存在"），且**不回显绝对路径**（脱敏）。
- 解析失败必须**指名条目**（`path` + 失败字段名），不做"整包静默跳过"。
- 未识别头部 → 进 `raw_header_sha256`（不是错误、不是跳过），并在 `facts` 输出里可见。

## 七、已知边界（写进 README 与 `plan/06`）

1. v0 不含 `deb`/`rpm`/`apk` 容器、不含 registry 拉取、不含 `--against-tag`。
2. 不做模糊二进制对齐、不做符号级语义 diff（diffoscope / elf_diff 领地）。
3. 仅同 sha256 判改名；同哈希多处出现即不判。
4. 跨平台差异只在 CI 矩阵验证，本机仅 Windows + Git Bash 实测（见 `plan/00` §八）。
