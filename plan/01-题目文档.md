# 10-20-build-diff-ledger · 构建产物差异归因账本（题目文档）

> - **性质**：不参赛项目题（无赛事锚点；含金量锚点 = 需求侧原话 + 生态覆盖矩阵实测 + 可复算分类账本）
> - **目标产出**：仓库 `10-20-build-diff-ledger`（Build Diff Ledger / 命令名 `bdiff`），发布 GitHub **公开仓库**，署名 yuluo554
> - **版本史**：v1 2026-10-20（初稿定稿；查证基准日 **2026-10-20**，GitHub API 快照时间戳 2026-10-19T17:50Z–18:10Z UTC）
> - **交付形态**：**纯本地 CLI（单二进制，零运行时依赖、不跑构建、不联网）**。单一形态，不设备选：所有判断都由两个已产出的产物文件的字节复算得出，不调用网络、不调用构建系统、不加载模型权重。
> - **定位宣言**："diffoscope 回答'哪里不同'，reprotest 回答'是否稳定'，strip-nondeterminism 回答'怎么抹平'，buildinfo 回答'怎么重建'——**没人回答'这是哪一类差异、有几处、归一化后还剩多少真差异、最少改哪几项就一致'**。本工具把两份已产出的构建产物转成可复算的分类账本 + 最小原因集 + CI 门禁。"
> - **与 diffoscope 的一句话边界**：diffoscope 是**差异渲染器**（把不同之处逐层展示给人看），本题是**归因账本器**（把不同之处归到闭合分类、给出计数与残留字节、并搜索最小归一化原因集）；本题不重实现它的 comparator，也不做模糊二进制对齐。

## 一、介绍

### 1.1 痛点

可复现构建（reproducible builds）的排查现场有一组固定动作：`diffoscope` 看差异 → 人眼判断差异属于哪一类 → 猜一组 `SOURCE_DATE_EPOCH`/`umask`/`uid`/构建目录设置 → 重跑一次构建 → 再看看是不是一致。

问题在于**中间那一步没有任何工具**：

- 差异**看得见**（diffoscope 给全文报告），但**数不出来**：这份报告里有几处时间戳差异、几处属主差异、几处压缩器参数差异，没人给计数；
- **归一化是反事实实验**："假设时间戳、属主、构建目录都抹平，这两个产物是否字节相等？"——这需要在不重新构建的前提下，对**已产出**的产物做归一化后再比，现有工具没有这个模式；
- **最小原因集**：到底是"只差 mtime"还是"mtime + uid 都差"，现有工具只能给一长串差异行，不能给"最少改哪几项就一致"；
- **CI 门禁**：想要"只有元数据差异 → 放行；有真实内容残留 → 失败"，现在只能自己写脚本解析 diffoscope 文本。

## 二、任务要求

首期 **5 个模块**，扩展项另列。每模块写清 **输入 / 输出 / 确定性纪律 / 验收**。全模块共享 `data/README.md` §四的数值口径（T1–T12 闭合分类定义、归一化 op 语义、树摘要算法、退出码、`|S|≤12` 上限、幂等性要求），**不得在代码或文案中另立第二套口径**。

### 模块① `align` — 结构对齐

- **输入**：`--left` / `--right` 两个产物路径，支持：目录、`tar`、`tar.gz`、`zip`、`whl`、`jar`、OCI layer tar（`--layer-kind=oci`）。
- **输出**：规范化条目表——每条 `(relpath, kind, size, sha256)`，按 `relpath` **字典序**（UTF-8 字节序）排列；归档内条目路径统一为 `/` 分隔、去前导 `./`、不做大小写折叠。
- **引擎**：归档按容器**解到内存流**（不落临时目录）；`whl` = zip + `*.dist-info/` 视为普通条目（不特殊处理）；`jar` = zip；OCI layer tar 不解析镜像配置，只处理层内条目。
- **改名判定纪律**：**仅当两侧唯一剩余条目的 `sha256` 相等时判为改名（RENAMED）**；不做模糊匹配、不做相似度阈值、不做二进制对齐——模糊对齐是 diffoscope 的领地。同一哈希出现多次 → 不判改名，各自记 `ADDED`/`REMOVED`。
- **确定性纪律**：同输入两次运行 JSON **逐字节一致**；不写时间戳、不写绝对路径、不写主机名；条目顺序由 `relpath` 字节序决定，与归档内存储顺序无关。
- **验收**：样张（同树 + 1 改名 + 1 新增）产出**精确等于** `data/golden/align/basic.json` 的期望集合（`ADDED`/`REMOVED`/`RENAMED`/`SAME` 四类计数与逐条 relpath）；同一输入双跑字节一致。

### 模块② `facts` — 事实抽取

- **输入**：模块① 的条目表 + 条目字节流。
- **输出**：扁平事实记录 `(path, key, value)`，稳定排序；不可解析部分**整体**进 `raw_header_sha256`。
- **抽取面**：
  - **tar / zip / gzip 头**：`mtime`、`uid`、`gid`、`uname`、`gname`、`mode`、`typeflag`（tar）；`external_attr`、`create_system`、`date_time`（zip）；`mtime`、`xfl`、`os`（gzip 成员头）。
  - **ELF**：`build-id`（`.note.gnu.build-id`）、`.comment` 全文、DWARF `producer` / `comp_dir`、节表偏移与大小。
  - **PE**：`TimeDateStamp`、`CheckSum`、`Rich` header 存在性与字节显影。
  - **Mach-O**：`LC_UUID`、`LC_BUILD_VERSION`（`minos`/`sdk`/`tools`）。
- **纪律（硬）**：每个受支持的 `key` 必须有独立单测；**未知字段不得静默丢弃**——解析器未识别的头部/元数据区必须计入 `raw_header_sha256`，并在 `facts` 输出里出现 `key="raw_header_sha256"`。任何"我没看懂所以跳过"的路径视为缺陷。
- **确定性纪律**：事实按 `(path, key)` 字节序排序；数值统一十进制字符串，不写本地化格式；`raw_header_sha256` 覆盖范围在 `data/README.md` §四.3 一处定义。
- **验收**：每 `key` 一个单测（合成样本，含未知扩展头的反例样张）；反例样张必须产出 `raw_header_sha256` 且与手工计算值一致。

### 模块③ `attribute` — 归因引擎

- **输入**：两侧 `facts` + `align` 条目表。
- **输出**：差异点列表，每点挂**闭合分类法**的 `rule_id`（T1–T12），附 `path`、`key`、`left`/`right` 值、`bytes_delta`；另出 `residue_bytes`（归一化后仍不同的字节数）。
- **闭合分类法**（定义只在 `data/README.md` §四.1）：
  | rule | 类别 | 典型触发 |
  |---|---|---|
  | T1 | 时间戳 | tar/zip/gzip `mtime` 不同 |
  | T2 | 属主 | `uid`/`gid`/`uname`/`gname` 不同 |
  | T3 | 权限 | `mode` / `external_attr` 权限位不同 |
  | T4 | 路径前缀 | 条目 relpath 的根前缀不同（构建目录改名） |
  | T5 | 条目顺序 | 条目集合相同、存储顺序不同 |
  | T6 | 压缩器参数 | gzip `xfl`/`os`、压缩级别线索不同 |
  | T7 | 归档头字段 | 归档级版本/格式/尾部字段不同 |
  | T8 | 工具链串 | `.comment`、编译器版本串、`producer` 不同 |
  | T9 | 调试符号与 build-id | `build-id` 不同 / DWARF 段存在性不同 |
  | T10 | 签名 blob | 签名段存在性与内容不同 |
  | T11 | 构建路径与环境 | `comp_dir`、内嵌绝对路径、locale/环境串不同 |
  | T12 | 未解释 | 归不进 T1–T11 的任何差异 |
- **归一化 op**：每个 Tn 对应一个**纯函数**归一化 op（`normalize_op(Tn, artifact) -> artifact`），语义写死在 `data/README.md` §四.2；op **必须幂等**（`normalize(normalize(x)) == normalize(x)`）。
- **集合 S 下的树摘要**：`tree_digest(S) = sha256( concat over sorted relpath of (relpath ‖ 0x00 ‖ sha256(normalize_S(entry))) )`，排序用 relpath 字节序，拼接规则一处定义。
- **确定性纪律**：差异点按 `(relpath, key, rule_id)` 排序；`residue_bytes` 由实际字节比对得出，不由分类推导；归一化后的产物不落盘（内存流处理）。
- **验收**：
  - 12 组样张（单因 8 / 双因 2 / 真改代码 1 / 混合 1）**分类命中率 100%**，期望集在 `data/golden/attribute/`；
  - `normalize(normalize(x)) == normalize(x)` 逐 op 断言；
  - `residue_bytes` 与**手工 `cmp` 计数**一致（golden 里记录手工值与其复现命令）。

### 模块④ `minimize` — 最小原因集

- **输入**：`attribute` 的差异点列表 + 分类法 T1–T12。
- **输出**：`minimal_cause_set`：满足 `tree_digest(S) 相等` 的**最小**规则集合 S；并列时按规则 id 字典序破平；无解时输出 `null` 且 `residue_bytes > 0`。
- **引擎**：按 `|S'|` 升序搜索（`|S| ≤ 12` 全穷举可接受，2^12 上界）；每个候选集只做一次内存归一化 + 一次摘要计算；命中即停（已按大小升序，故首个命中即最小）。
- **确定性纪律**：候选枚举顺序固定（先按基数、再按字典序）；不做随机化、不做启发式剪枝（剪枝会破坏"最小"的可复算性）；无解与"没有差异"必须区分（后者 `S=∅` 且 `residue_bytes=0`）。
- **验收**：
  - 只差 mtime → `[T1]`；
  - mtime + uid → `[T1,T2]`，**不得返回超集**（显式断言 `len(S)==2`）；
  - 真改代码 → `null` 且 `residue_bytes > 0`；
  - 混合样张 → 返回的最小集能复算出两侧摘要相等。

### 模块⑤ `report` — 报告与 CI 门禁

- **输入**：`attribute` + `minimize` 结果。
- **输出**：`report.json`（固定键序的规范 JSON）+ `report.md`（渲染视图，逐字节 golden）；退出码。
- **报告固定键**（顺序写死）：`schema_version`、`tool_version`、`left`/`right`（只写输入 basename 与 sha256，不写绝对路径）、`counts`（T1–T12 逐类计数 + `total`）、`renamed`、`added`、`removed`、`residue_bytes`、`minimal_cause_set`、`residual_items`、`notes`。
- **退出码语义**：`0` = 完全一致（逐字节，`S=∅` 且 `residue_bytes=0`）；`2` = **仅元数据差异**（所有差异都被 T1–T11 解释且归一化后一致）；`3` = **有残留**（`residue_bytes > 0` / 含 T12）；`1` = 用法错误或输入不可解析（**本表补定**，避免"读不了"被当成"一致"）。
- **`--budget` 白名单**：`--budget=T1,T2` 表示 CI 允许这两类差异存在 → 归一化后一致时退出 `0`（报告里仍逐条列出被放行的差异与计数）；`--budget` 不含实际出现的类别 → 不下调退出码。
- **确定性纪律**：不写运行时刻、不写绝对路径、不写主机名/用户名/locale；键序写死；同一输入双跑 `report.json` 与 `report.md` 均逐字节一致；`report.md` 不含任何时间性文案。
- **验收**：`data/golden/report/` 逐字节比对；退出码矩阵 **4 行全覆盖**（0/1/2/3 各一条样张）；`ci/example.yml` 里的门禁示例可本地跑通（不联网）。

| 确定性报告 | `bdiff compare --out` 产出的 `report.json`/`report.md` | 双跑逐字节 + golden 比对 |

## 三、提交材料

1. **单二进制产物**：`dist/bdiff-<os>-<arch>`（发布时手工上传 Release 附件，本地留副本并记录 sha256）；源码 `cmd/bdiff/` + `internal/` 可在干净环境用 Go 工具链重建。
2. **样张生成器**：`tools/gen_fixtures/`（Go 程序），按 `data/README.md` §三的合成纪律程序化生成 12 组样张——同源码、不同 `SOURCE_DATE_EPOCH` / `umask` / `uid` / 构建目录，构建两次；生成物可重建、字节确定。
3. **golden 集**：`data/golden/{align,facts,attribute,minimize,report}/`，每个 golden 文件附生成命令与手工复现命令。
4. **README 与发布留档**：`README.md`（安装、三场景最小复现、字段说明、已知边界）、`plan/RELEASE-M6.md`（干净环境验证、tag 与 Release 附产物、sha256 记录）。

**受众**：发行版打包者（Debian/Fedora/Arch 的 reproducible 工作流）、可复现构建维护者、供应链工程师（发布门禁 / 供应商产物核对）。

**时代性**：可复现构建已成主流发行版的发布要求，而"两个产物为什么不一样"仍靠人读 diffoscope 报告；构建环境越复杂（容器、交叉编译、多工具链），分类计数与归一化残留的价值越高。

**开源空白（三行结论，⬜ 软论据）**：
1. 差异渲染、稳定性测试、抹平、重建指令四件都有成熟工具，生态并不空白。
2. 没有工具对**已产出的两个产物**做"闭合分类 + 逐类计数 + 归一化后残留字节"。
3. 没有工具给出"最少抹平哪几项就一致"的最小原因集，也没有把该结论直接变成 CI 退出码。

## 六、边界与非目标

- **不做 SBOM / 许可证 / 合规审计**：该方向已有成熟占位工具，且属本题禁区；本题不解析依赖清单、不判定许可证。
- **不重实现 diffoscope 的整套 comparator**：不做逐行文本 diff、不渲染人类可读的深层差异树。
- **不做模糊二进制对齐**（diffoscope 领地）：不改名判定不做相似度、不做字节级重排对齐。
- **不做符号级语义 diff**（elf_diff 领地）：不比较函数/符号语义，只比较头字段与节表事实。
- **不替代 reprotest**：本题**不跑构建**，只处理已产出的产物；"是否稳定"由 reprotest 回答。
- **不承诺自然语言"为什么"**：只承诺可复算的**分类计数 / 残留字节 / 最小原因集**；不生成"大概是编译器升级导致"这类猜测。
- **隐私红线**：纯本地、零网络；报告不写绝对路径、主机名、用户名；不读取产物目录之外的文件。
- **品牌隔离**：本题只做构建产物字节层归因；文档与代码中不提名本系列其他项目，与其他项目零代码复制。
- **首期范围限定**：v0 **不含** `deb`/`rpm`/`apk`、不含 registry 拉取、不含 `--against-tag`；扩展项不进首期判定路径。
- **结论纪律**：分类账本是"两份产物差异的机械归因"，不等于"这一处差异有害/无害"；报告必须同时给出归一化前后摘要与残留字节，由人决定是否放行。
